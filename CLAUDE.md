# Project notes for Claude

## Stack
Expo (expo-router) + React Native + Reanimated, in `apps/mobile`. Avoid web-only or three.js-based libraries (shadergradient, react-three-fiber) unless explicitly requested; use `expo-linear-gradient`, `react-native-svg`, or `@shopify/react-native-skia` instead.

Use `animate-expo` for native motion, `break-ui` to test screens with worst-case data (long names, Arabic/French text, empty lists).

## Loading indicator
`apps/mobile/src/ui/thinking-orb*.tsx` wraps [thinking-orbs](https://github.com/jakubantalik/thinking-orbs) (MIT, Jakub Antalik; license in `docs/third-party/`). Web uses the published canvas component; native is Skia, adapted from the repo's React Native port (not verified on a device). Use `ThinkingOrb` for prominent loading states; keep `ActivityIndicator` in small buttons.

## Visual language
Verses live in `features/spirit/verses.ts` (Arabic + English, Amiri font); home shows one per day, `/verses` lists all. Keep Arabic text exact (Uthmani script).
Wabi-sabi first: warm washi-paper/earth palette in `ui/palette.ts`, uneven hand-cut corners (`wobble`), restraint. Victorian touch: EB Garamond headings (`display`) and the `Ornament` fleuron divider under page headings. Conceptual-sketch touch: hand-drawn, slightly irregular SVG strokes. Body text stays on the system font. Use palette tokens, never hardcoded colors.

## Medicine & treatments
`features/medicine/`: static generic-name directory (no doses); each medicine = how much (amount+unit) / how often (daily, every N days, weekdays, as-needed with max per day + min gap) / for how long (or ongoing); dose logging, doctor prescribing via `prescribe_treatment` (needs an active `medical_profile` grant). Migration `202610080001`. Local dose reminders (reminders.ts, planned 7 days ahead), stock/refill tracking and adherence reports (migration 202610080002).
Built-in articles/blogs live in `features/content/library.ts` (not clinician-reviewed; needs medical review) and merge with DB `blog_articles`.

## Map (Mapbox)
`features/discovery/`: Mapbox GL JS v3.14 runs in one HTML page (`map-runtime.ts`), shown on web as a same-origin iframe of the static `public/map-frame.html`+`map-frame.js` (generated by `node apps/mobile/scripts/build-map-frame.mjs` from `map-runtime.ts`; a test checks they match; no inline script so the Vercel CSP allows it) (`mapbox-view.web.tsx`) and `react-native-webview` on native (`mapbox-view.tsx`), because `@rnmapbox/maps` needs a downloads token we don't have. The bridge carries plain data and ids only (no URLs/markup); the parent builds Call/Directions (Google Maps) links and routes to `/doctors/<id>`. Pure logic and tests in `map-logic.ts`. Env: `EXPO_PUBLIC_MAPBOX_TOKEN`, `EXPO_PUBLIC_MAPBOX_STYLE_URL` (mobile), `VITE_MAPBOX_TOKEN`, `VITE_MAPBOX_STYLE_URL` (admin), in git-ignored `.env.local`. Data: migration `202610100001` (extends `care_providers`, RPC `list_map_locations`, admin RPCs); the admin page `/locations` (permission `providers.verify`) manages them (picker, CSV import as drafts, duty). Verified doctor practice locations appear automatically. The API's `/v1/care/nearby` is no longer used by the map.

## Donations
Migration `202610110001` (apply after 202610070001, 080001, 080002, 090001, 100001); then `202610120001` (donor comments need approval, `beneficiary` invite role, `donation_analytics`, `bulk_review_comments`). Cases (`donation_cases`, categories, gallery `donation_case_media`) are admin-managed via RPC `admin_save_donation_case` (permission `donations.review`, admin page `/donations`). Bank accounts (`donation_bank_accounts`) are platform-owner only and revealed only to someone holding an order. Donors (anonymous allowed, secret token kept in AsyncStorage `ihssan.pledges.v1`) create an order (`create_donation_pledge`, ref `IH-XXXXXXX`, 48h), transfer directly to the family, upload receipts (private `donation-receipts` bucket), and an admin or per-case fund collector confirms (`review_pledge`); `recompute_case_total` updates raised = initial + confirmed. Collectors join by single-use invite link `/collect/accept?token=…`. Mobile: `features/donations/`, routes `/give`, `/cases/[id]`, `/pledge/[id]`, `/collect`. Admin portal `features/donations/`: sidebar group "Giving & community" (overview analytics `/donations`, cases list, per-case workspace `/donations/cases/:id` with tabs Overview/Donations/Comments/Profile/Bank/Gallery/Team/Preview, donor comments bulk approve `/donations/comments`). Donor comments are public only once approved by admin, collector or beneficiary (patient/family invited via Team tab; they cannot see receipts). Mobile drawer item "My giving cases" → `/collect`. Not built: case updates timeline, donor notifications. Needs legal review for Morocco before launch.

## Deploy & admin security
- API on Fly.io (`services/api/fly.toml`, app `ihssan-api`, `https://api.ihssanapp.com`). Set secrets with `fly secrets set` using real values; never paste `<placeholders>` (angle brackets caused "Session is invalid or expired" once). Check by length/prefix via `fly ssh console`.
- Admin portal (`alhamdulilah.ihssanapp.com`) requires TOTP MFA (aal2): `MfaGate` in `AdminConsole.tsx` enrols/challenges, and the API rejects `/v1/admin/*` without an `aal2` token. TOTP must be enabled in Supabase Auth. Direct Supabase RPCs are not yet aal2-gated at DB level.
